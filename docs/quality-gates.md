# 质量门禁与修复回路

流水线里有两道**强制门禁**：不达标就中断，差稿不进入下一步。
门禁的价值不在于「打分」，而在于**给出可执行的修复方向**并**阻断错误的传播**。

## 一、门禁位置

```
p1 context → p2 outline → p3 design → p4 scene
                                          │
                                  ┌───────▼────────┐
                                  │ p5 创意门禁     │  四维评分
                                  └───────┬────────┘
                                     FAIL │ 中断 ──▶ 回到 p3/p4 修改
                                     PASS ▼
                                   p6 draft
                                          │
                                  ┌───────▼────────┐
                                  │ p7 评审门禁     │  规则 ×30% + LLM ×70%
                                  └───────┬────────┘
                                     FAIL │ 中断 ──▶ 回到 p6 重写
                                     PASS ▼
                                   p8 absorb → 记忆图谱
```

## 二、p5 创意门禁（创意/结构层）

在**动笔之前**，先审「结构」——因为正文写错再改，代价最高。

| 维度 | 考察 |
|:---|:---|
| 结构对齐 | 本章角色/事件是否与整体结构一致？出场是否有伏笔感？ |
| 信息漏出控制 | 是否直接交代了身世？是否违反「展示而非讲述」？ |
| 钩子密度 | 悬念是否足够把读者带到下一章？ |
| 场景设计 | 场景转换是否合理？每场是否推动主线或角色弧？ |

判定（阈值见配置 `quality_gates.creative_gate`）：

```
任一维度 < min_dimension          → FAIL
总分      < min_total            → FAIL
否则                              → PASS，进入撰稿
```

## 三、p7 评审门禁（文本质量层）

两级评审，**规则引擎 + LLM**，各有分工：

### 1. 确定性规则引擎（`gates.py`）
零成本、可复现，负责「机械性问题」：
- 笔误 / 混用检查（的的地得、在再、那哪……）
- **信息漏出**正则（「他的父亲」「他出生在」「原来他」……）
- 风格违规（连续逗号、感叹号滥用、小说腔、过度修辞、上帝视角、解释性叙述）

规则分：`score = max(0, 90 - 惩罚和 × 40)`。

### 2. LLM 五维评审
负责「文学性」维度：叙事节奏 / 对话真实感 / 场景画面感 / 人物一致性 / 信息漏出控制，
外加「技法执行率」的加减分运算。

### 3. 综合
```
综合分 = 规则分 × rule_weight + LLM分 × llm_weight      （默认 0.3 / 0.7）
PASS 条件 = 综合分 ≥ min_total  且  LLM分 ≥ min_llm_score
```

用规则引擎兜底「机械问题」，用 LLM 判「文学问题」——单靠 LLM 会漏机械错误，
单靠规则抓不住文学质感，两者互补。

## 四、修复回路（Repair Loop）

门禁 FAIL 不是终点，而是**回到对应的上游阶段**：

| FAIL 阶段 | 回退到 | 修复动作 |
|:---|:---|:---|
| p5 创意门禁 | p3 design / p4 scene | 重做场景与冲突设计（结构性问题不能靠改字解决） |
| p7 评审门禁 | p6 draft | 按 `top_improvements` 重写正文 |

由于每个阶段的产物落盘 + 进度持久化（`progress.json`），
可以**只重跑失败的那一步**：

```bash
# 只重跑设计（改结构）
python3 pipeline.py --config your_novel.json --chapter 4 --step design
# 只重跑正文（改文字）
python3 pipeline.py --config your_novel.json --chapter 4 --step draft
```

## 五、稳定性要点

- **结构化输出用低温**：门禁 / 吸收阶段 `temperature=0.3`；
  创作阶段（design / draft）才用 `0.5~0.8`。
- **JSON 容错解析**：LLM 常把 JSON 包在 ```json 围栏里，
  `gates.parse_llm_json()` 会去围栏 + 正则提取，避免解析失败导致误判。
- **评分校准**：提示词里写清「平均 75 已是良好，90+ 才代表几乎没有改进空间」，
  防止 LLM 一律给高分（评分虚高会让门禁形同虚设）。
