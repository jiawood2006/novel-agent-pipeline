# 架构：Agent 职责与协作

本框架把「写一章小说」拆成一条**有依赖关系的阶段流水线**。每个阶段由一个
职责单一的 Agent 负责，阶段之间通过**结构化产物文件**交接，而不是靠上下文记忆——
这是「防漂移」的第一道保险。

## 一、整体架构（ASCII）

```
                         ┌──────────────────────────┐
                         │   四维记忆图谱 memory.py   │
                         │ entity/temporal/causal/   │
                         │        semantic           │
                         └─────────────┬────────────┘
                    写前检索 ↑               ↓ 写后吸收
                               │               │
   ┌───────────┐   ┌───────────┐   ┌───────────┐   ┌───────────┐
   │ p1 检索    │──▶│ p2 大纲    │──▶│ p3 设计    │──▶│ p4 场景    │
   │ Context   │   │ Outline   │   │ Design    │   │ Scene     │
   └───────────┘   └───────────┘   └───────────┘   └─────┬─────┘
                                                          │
                                    ┌─────────────────────┘
                                    ▼
   ┌───────────┐   ┌───────────┐   ┌───────────┐   ┌───────────┐
   │ p8 吸收    │◀──│ p7 评审    │◀──│ p6 撰稿    │◀──│ p5 门禁    │
   │ MemoryEng │   │ Editor    │   │ Draft     │   │ Gate      │
   └───────────┘   └───────────┘   └───────────┘   └───────────┘
        │                                                 │
        └──────────────▶ 记忆图谱更新（下一章更准）        └─ FAIL 则中断
```

- **7 个 Agent** 承担 p1~p7（见下表）。
- **1 个引擎**：`pipeline.py`（编排）+ `memory.py`（记忆），承担 p8 与调度。

## 二、7 个 Agent 的职责

| # | 阶段 | Agent | 输入 | 输出 | 一句话职责 |
|---|:---:|:---|:---|:---|:---|
| p1 | context | `ContextAgent` | 记忆图谱 + 上章结尾 | `context_ch{N}.md` | 把「方向 + 记忆 + 前情」压成写前上下文包 |
| p2 | outline | `OutlineAgent` | 上下文包 + 本章配置 | `outline_ch{N}.md` | 生成含事件链 / 温度曲线的章节大纲 |
| p3 | design | `DesignAgent` | 大纲 + 记忆 | `design_ch{N}.md` | 产出场景分段 / 冲突推进 / 伏笔设计 |
| p4 | scene | `SceneAgent` | 设计稿 + 大纲 | `scene_ch{N}.md` | 拆成 3-5 个可写场景，控制节奏曲线 |
| p5 | gate | `GateAgent` | 场景 + 设计 + 大纲 | `gate_ch{N}.json` | 四维评分，不达标即拦截 |
| p6 | draft | `DraftAgent` | 全部场景 + 设计稿 | `draft_ch{N}.md` | 一次性写完整章正文 |
| p7 | editor | `EditorAgent` | 正文初稿 | `editor_ch{N}.json` | 规则初筛 + LLM 五维评审 |
| p8 | absorb | `MemoryAbsorber`（记忆引擎） | 定稿正文 | `absorb_ch{N}.json` | 提取事件 / 角色 / 线索 / 主题写回图谱 |

## 三、为什么这样分工（设计动机）

### 1. 单一职责 = 可拦截
每个 Agent 只做一件事，产出可被**确定性校验**。门禁阶段（p5/p7）能独立于创作
给出 PASS/FAIL，不合格的稿子不会流入下一步，避免「一步错、步步错」。

### 2. 结构化交接 = 防漂移
Agent 之间不靠「上一轮对话记忆」，而是读**磁盘上的产物文件**。
好处：
- 可复现、可审计（每一步的输入输出都留痕）；
- 可单独重跑某一步（`--step design`），不必重跑全链；
- 换模型 / 换供应商不影响阶段契约。

### 3. 记忆外置 = 一致性
长篇小说最容易崩的是「一致性」——角色设定、时间线、伏笔。本框架把记忆
外置成**四维图谱**（见 `docs/memory-graph.md`），每章写完立刻回写，
下一章写前再检索回来，形成闭环。

### 4. 分工而非一个巨型 prompt
一个 prompt 同时干「定结构 + 设计场景 + 写正文 + 自我评审」，会出现：
职责冲突（又当运动员又当裁判）、注意力稀释、评分虚高。
拆成流水线后，**评审 Agent 与撰稿 Agent 相互独立**，评分更可信。

## 四、阶段契约的稳定性

所有 Agent 继承同一个 `BaseAgent`（`agents/base.py`）：

```python
build(chapter)        -> (system_prompt, user_prompt)
run(chapter, dry_run)-> 组装提示词 / 调用 LLM / 返回门禁结果
postprocess(raw, ch)  -> 写图谱、判定门禁（子类覆写）
```

新增一个阶段，只需：写一个 `prompts/xxx.md` + 一个 `agents/xxx_agent.py`，
再在 `pipeline.py` 的 `STAGES` 里登记依赖与产出。**流水线的形状由数据描述，
不是写死的流程代码。**
