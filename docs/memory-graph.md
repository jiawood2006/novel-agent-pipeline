# 记忆图谱模型（MAGMA 四维图谱）

长篇小说的「一致性」问题（角色崩、时间乱、伏笔丢、主题飘）本质上是
**记忆管理问题**。本框架把小说记忆拆成四个**正交**图谱，各管一件事，互不污染。

## 一、四个图谱

```
图谱         小说里对应什么              解决的问题
──────────────────────────────────────────────────────────────
实体图谱      人物关系网                 角色关系 / 状态 / 设定不漂移
 👥 entity
时间图谱      故事时间线                 事件先后、闪回、并行不出错
 📅 temporal
因果图谱      伏笔 → 回收链路            埋的线有人收、动机链不断
 🔗 causal
语义图谱      主题 / 世界观 / 写作约束    主题不跑偏、规则不被违反
 🎭 semantic
```

四个图谱共享同一批实体名（角色 / 地点），但边与属性的语义完全不同：

- 实体图谱的边 = 「谁和谁是什么关系」（带强度、互动模式）；
- 时间图谱的边 = 「A 在 B 之前」（时序）；
- 因果图谱的边 = 「A 导致 B」（因果，含 `status=open/resolved` 的线索）；
- 语义图谱的边 = 「概念落在哪个主题 / 哪条规则下」。

## 二、双流写入（Two-Path）

| 路径 | 时机 | 做什么 | 特点 |
|:---|:---|:---|:---|
| **Fast Path（即时）** | 每章 `p8 absorb` 后立即执行 | 事件进时间图谱、线索进因果图谱、新角色进实体图谱、主题进语义图谱 | 确定性、快、便宜 |
| **Slow Path（异步）** | 空闲时（可选） | 由 LLM 做跨章因果推理、主题提炼、世界观关联修正 | 深、慢、贵 |

本框架的 `pipeline.py::MemoryAbsorbStage.ingest()` 实现了 Fast Path；
Slow Path 留给使用者在批处理时扩展（例如每完成一卷跑一次图谱推理）。

## 三、写前检索（query_for_chapter）

写第 N 章前，`ContextAgent` 调用 `memory.query_for_chapter(N, cfg)`，
把记忆「投影」成一个上下文包：

```
👥 相关角色及关系网      → 谁在本章、谁认识谁、关系强度
📅 时间线节点            → 阶段划分 / 近期事件
🔗 未闭合线索            → 本章该收哪条线、该埋哪条线
🎭 活跃主题              → 本章不能跑偏的主题
⚠️ 生效写作约束          → 不可违反的红线
```

检索结果直接进入 p1 的提示词，成为后续所有阶段的共同前提。

## 四、存储与依赖

- 存储格式：**纯 JSON**（`{nodes, edges}`），零第三方依赖即可读写，
  保证 `--dry-run` 离线可跑。
- 落盘位置：`<output_dir>/memory.json`。
- 可选增强：装了 `networkx` 后可用 `NovelMemory.to_networkx()` 把四图转成
  `nx.DiGraph` 做图分析（中心性、社区、跨图桥接等）。

## 五、为什么「四图」而不是「一张大图」

把它们混成一张图，会出现两类污染：

1. **语义歧义**：一条边既可能是「因果」也可能是「时序」，无法区分——
   导致「因为 A 所以 B」和「A 在 B 之前」被当成同一种关系处理。
2. **检索噪声**：查「本章出场角色」时把大量事件节点也带出来，
   上下文被无关信息淹没。

拆成四图后，每种检索只走对应的图，**检索精度与提示词质量同时提升**。

## 六、建库建议（给真实项目）

1. 用小说配置播种最小图谱（角色 / 主题 / 阶段）——本框架 `seed_from_config()`。
2. 从**人物卡 / 世界观文档 / 已写正文**批量吸收（批处理脚本）。
3. 每写完一章跑 `p8`，让 Fast Path 持续补图。
4. 定期跑 Slow Path 做因果推理，清理过期线索。
